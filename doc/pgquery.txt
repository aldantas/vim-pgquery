INTRODUCTION                                                       *pgquery*

vim-pgquery executes the nonblank SQL block under the cursor, or an explicit
line range, with psql. Named connections are persisted centrally, while the
active connection is local to each buffer. Selecting a connection does not
contact PostgreSQL unless eager vim-dadbod-completion integration is active;
otherwise access occurs only when a query or terminal is started.

==============================================================================
REQUIREMENTS                                           *pgquery-requirements*

Vim 8 or Vim 9 with JSON support is required. |:DBExecute| needs |+job| and
|:DBTerminal| needs |+terminal|. Those features are checked only when their
commands are used. The psql program must be installed and available in $PATH.
Neovim is not a supported target.

==============================================================================
COMMANDS                                                   *pgquery-commands*

                                                               *:DBNew*
:DBNew          Prompt for a unique friendly name and a PostgreSQL URL. URL
                input is visible. The URL must start with postgres:// or
                postgresql:// and contain no whitespace. The new connection
                is selected for the current buffer and remembered for
                its file path.

                                                           *:DBConnect*
:DBConnect      Select and remember a connection for the invoking file. A
                popup is used when |popup_menu()| exists, with |inputlist()| as the
                fallback. Canceling does not alter the selection. Labels omit
                passwords, query parameters, and fragments.

                                                        *:DBCurrent*
:DBCurrent      Display the current buffer's full saved connection URL in the
                command area. It includes any password and URL parameters.
                A disconnected buffer reports an error.

                                                            *:DBEdit*
:DBEdit [name]  Change a saved connection's name and URL. If {name} is omitted,
                choose one from the connection picker. URL input is visible.
                Leave the URL prompt
                blank to keep the current URL. Renaming also updates every
                file mapping that refers to the old name. Loaded buffers
                using the connection are updated immediately.

                                                          *:DBDelete*
:DBDelete [name]
                Delete a saved connection after confirmation. If {name} is
                omitted, choose one from the connection picker. File
                mappings that refer to it are removed and loaded buffers using
                it are disconnected.

                                                       *:DBExecute*
:[range]DBExecute
                Run {range} asynchronously. A Visual selection supplies the
                range automatically. Without a range, run the nonblank block
                containing the cursor; blank lines delimit blocks. Output and
                errors are accumulated independently for every job and shown
                in a read-only scratch split. A nonzero psql exit status is
                reported. The temporary SQL file is removed when the job
                exits, or the transaction execution completes. See
                |pgquery-transactions| for sessions spanning executions.

                                        *g:pgquery_confirm_destructive*
                DELETE and TRUNCATE outside a live transaction in the current
                buffer require confirmation, with Cancel as the default.
                Canceling returns without sending SQL. Only the executed
                block or range is checked. Keywords are case-insensitive;
                comments, strings, and quoted identifiers are ignored.
                A block starting a new transaction also asks; subsequent
                executions inside it do not. Destructive SQL after a tracked
                COMMIT; or ROLLBACK; requires confirmation again, including
                within the same execution. Detection follows the supported
                transaction controls below, not a full SQL or psql parser.
                The warning is enabled by default. Disable it with: >
                  let g:pgquery_confirm_destructive = 0
<

                                                        *:DBTerminal*
:DBTerminal     Open psql with the current buffer's connection in a Vim
                terminal split.

No command executes through a shell: URLs are process argument-list entries.

==============================================================================
FILE SELECTION                                                 *pgquery-files*

On entry to a file buffer, pgquery restores the last connection selected for
its exact absolute file path, resolving symlinks. DBNew and DBConnect save the
selection immediately. It survives query execution, buffer switches, reopening
the file, and restarting Vim. Files in the same directory remain independent.

Selections use b:pgquery_connection and are never global. A file without a
saved connection stays disconnected until DBConnect or DBNew is used. A stale
mapping or missing named connection disconnects the buffer and reports an
error. Unnamed buffers keep selections in memory; after naming the buffer,
using its connection remembers the file path too.

The selected URL is mirrored to buffer-local b:db for compatibility with
vim-dadbod and vim-dadbod-completion. Pgquery removes that value when it
disconnects the buffer, but only when b:db still contains the value pgquery
assigned; a value subsequently set by another plugin is preserved.

When vim-dadbod-completion is loaded, pgquery connects and starts warming its
cache after restoring an SQL file's connection. This avoids delaying the first
completion while its FileType hook waits for b:db.

                                      *g:pgquery_eager_dadbod_completion*
Set the following before plugins load to retain lazy initialization: >
  let g:pgquery_eager_dadbod_completion = 0
<

STATUSLINE                                             *pgquery-statusline*

Append the selected connection name to an existing |'statusline'|: >
  set laststatus=2
  set statusline+=%{pgquery#statusline()}
<
                                                   *pgquery#statusline()*
pgquery#statusline() returns " [DB: name]" for the statusline's buffer, or an
empty string when disconnected. It uses the saved connection name, even when
that differs from the database in the URL. The value follows buffer changes,
connection renames, and deletions without showing credentials. While a
transaction session exists it returns " [DB: name; TX]".

When using Vim's default statusline, set a complete format first: >
  set statusline=%f%m%r%=%{pgquery#statusline()}\ %l:%c
<

TRANSACTIONS                                            *pgquery-transactions*

Start a transaction by executing a block whose first line is BEGIN;. Case and
surrounding whitespace are ignored. Subsequent DBExecute calls in that source
buffer use the same psql process and selected connection. Execute COMMIT; or
ROLLBACK; to end the transaction. The session closes after that execution
completes if its final tracked control ends the transaction. Statements after
a closing control in the same execution still run normally.

Supported controls are standalone BEGIN;, COMMIT;, and ROLLBACK; lines outside
SQL strings, quoted identifiers, dollar-quoted strings, and comments. Multiple
controls are tracked in execution order. Inline controls, aliases (e.g. END),
transaction options, and AND CHAIN are outside the tracking contract. Execute
complete SQL blocks.

Each execution has a separate result batch. Its mode-0600 temporary SQL file
is removed when a private completion marker arrives. Another execution in the
same buffer is rejected while it is busy; other buffers remain independent,
even with the same connection. DBTerminal uses a separate session.

SQL errors leave the process alive and preserve PostgreSQL's normal failed
transaction behavior. Execute ROLLBACK; to recover. Unexpected process exit is
reported and clears the transaction state without retrying SQL. Transaction
jobs ignore psql startup files, disable paging, and set ON_ERROR_STOP and
ON_ERROR_ROLLBACK off.

A buffer with a transaction cannot select a different connection or use DBNew.
DBEdit and DBDelete reject connections used by any open transaction before
changing storage. The statusline shows " [DB: name; TX]" while a session exists.

Hiding or switching buffers preserves the session. Deleting or wiping its
source buffer, disconnecting it, or exiting Vim closes the job and removes
pending temporary files. Closing the connection discards any open transaction.
Transaction state is only in memory and does not survive restarting Vim.

==============================================================================
STORAGE AND SECURITY                                         *pgquery-storage*

The default store is:

  ~/.vim/pgquery.json

Override it before pgquery loads: >
  let g:pgquery_store_path = '~/.config/vim/pgquery.json'
<
The document has this shape: >
  {
    "connections": {"local": "postgresql://user@localhost/app"},
    "files": {"/home/me/app/queries.sql": "local"}
  }
<
File keys are canonical absolute paths. Writes use an atomic rename,
and the store has mode 0600. If existing storage is malformed or has an invalid
schema, it is not overwritten. Correct it or move it before trying again.

Passwords in URLs are plaintext and protected only by filesystem permissions.
For stronger protection, omit the password and use .pgpass or another external
credential provider. Popup labels redact passwords and URL parameters.

Use |:DBEdit| to rename a connection or change its URL. Use |:DBDelete| to
delete one and remove all file mappings that refer to it.

MAPPINGS                                                   *pgquery-mappings*

No mappings are installed. Examples: >
  nnoremap <silent> <leader>dq :DBExecute<CR>
  xnoremap <silent> <leader>dq :DBExecute<CR>
  nnoremap <silent> <leader>dt :DBTerminal<CR>
<
